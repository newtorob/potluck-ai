# Focused presentation of saved answers

A reviewed answer outline can group existing cited excerpts under topic headings while keeping the full original answer/evidence expandable. This is a display projection, not a new inference result or an authority change.

`FocusedSourceAnswer` accepts a `ReviewedAnswerOutline` bound to the saved answer's exact text, status and ordered snippet IDs, plus the exact source content for every selected citation. Every selected snippet must be accounted for. Display blocks use exact source quotes with their existing citation IDs; metadata handling is limited to source labels, blank text and already visible duplicates. Conditional headings cannot be silently hidden as labels. Stale sources, changed answers, missing quote/coverage/citation, malformed plans or non-supported status fall back to the original `ReviewedPassageAnswer` surface. Full source and original output remain in an accessible disclosure.

The renderer accepts a separately reviewed outline or a validated saved automatic outline. No customer-specific content or outline belongs in shared application code. Current pilot data remains in private experiment artifacts. Qualify outline producers separately, including conditions, exceptions, citation correctness and unknown/conflicting evidence. Display tests are not model-quality qualification.

The reviewed-pilot endpoint accepts an opt-in `organize_answer` field. The raw API default is false. The reviewed desktop helper explicitly requests organization by default after qualification; callers can pass false to opt out. It adds at most one measured local organization call per eligible supported fixed-part answer, with a 768-token output cap and a 120-second result deadline within the original request deadline. The model returns only one supplied topic-set ID per numbered passage packet. Individual topics are the exact confirmed question parts; a paragraph answering several parts may use a combined ID. The application joins those exact questions in the section heading and copies the intact paragraph once. The model cannot write headings, summaries, quotes, facts or citations. Every question must be covered, every nonblank selected passage must appear exactly once, and blank excerpts remain accounted for. Source context stays visible after the question sections. Unknown/conflicting answers retain the original view.

Explicit plan-stage constraints also prevent a later numbered Fix step from becoming a before/prerequisite requirement without ordering language, preserve a literal Before-building list, and keep unasked Done-when completion separate from prior requirements. The native row enums and host/reload validation enforce these conservative structural rules. They do not replace semantic review or establish a general understanding of every policy's chronology.

A leading conditional paragraph stays attached to its adjacent passage only when both map to the same unique supporting source section. The host rejects detached packets and binds the saved outline to the question, confirmed parts, full original answer, exact claim content and source-support metadata. It preserves original order within each group. These checks establish structural integrity; a valid topic ID or complete JSON object does not establish correct meaning. Source-aware qualification must separately assess prerequisites, exceptions, time windows, object scope and question compatibility. Older saved outline versions keep their original interpretation without new inference.

An optional organization deadline returns the original answer while allowing that one already bounded local generation to drain. A late result is consumed and discarded, never persisted. Further optional organizers fall back while it drains. Explicit request cancellation retains normal runtime cancellation behavior. This prevents a display timeout from unloading the shared model. No extra call, retry, remote routing or background answer update is introduced.
A compact draft and binding digest are stored in original provenance. Reading, reviewing, exporting or reopening an answer reconstructs its display without inference. Normal source/review invalidation clears the provenance; corrected answers do not reuse original outlines. A grouping failure saves the valid original answer with a bounded fallback receipt. This is presentation only, and does not establish semantic relevance or factual correctness; fresh source-aware evaluation must assess those separately before enabling automatic requests.

The pilot scan also accepts an opt-in `preserve_heading_context` flag. This uses a separately versioned evidence parser that retains heading-only sections and avoids merging short bodies across different headings. A heading can carry a draft/proposed state or an exception prerequisite; it must reach the reviewed source draft before organization can preserve it. Explicit rescans with this parser change the document revision and invalidate older bound claims and answers through the normal review lifecycle. The raw API and personal vault retain their existing parser defaults. The qualified reviewed desktop scan explicitly requests heading preservation by default, with a caller opt-out. No sources are silently rescanned or approved.

The Markdown owner is shared with the existing evidence renderer, so raw HTML, unsafe links and external image loading keep the same restrictions. The component does not write to the API, rerun inference, approve an answer or record usefulness.
